# ロードマップ

Tessa は意図的に小さく保っています。ロードマップは「日本語で日常的に使える
デスクトップ」に必要なものから、その後の磨き込みへと並べています。

## 0.1.x — 土台を信頼できるものにする

- [ ] 対象マシンで DRM + libinput を実行し、レイアウトと入力の問題を直す。
- [x] バーのワークスペースクリック、ウィンドウチップの右クリック終了、
      フローティングのドラッグ/リサイズ、クリックでフォーカス、
      ランチャー入力の headless 自動テスト
      （`tests/interaction.sh`、`wlr-virtual-pointer-v1` を使用）。
- [x] フルスクリーン、xdg クライアントポップアップ、クリップボード、
      複数ウィンドウのフォーカスを `tests/interaction.sh`、
      `tests/popups.sh`、`tests/clipboard.sh` で検証。実際のマウス/
      キーボードでの確認は上の DRM 項目に含む。
- [ ] フローティング/リサイズ後の一時的な再描画漏れを修正する。対話操作の
      終了時に再配置して最終ジオメトリを公開するようにはしたが、ドラッグ中
      の見た目の検証には実ディスプレイが必要。
- [x] headless コンポジタを起動して状態/IPC と拡張フックを検証する小さな
      統合テストを追加する（`tests/smoke.sh`）。
- [x] ライセンスを決定する（MIT）。
- [x] Arch PKGBUILD と Debian パッケージ定義。ビルドと依存関係で
      wlroots 0.19 を明示的に固定。
- [ ] CI でビルド・署名されたパッケージとリリース成果物。

## 0.7 — カスタマイズ性の同等以上

Hyprland/Niri の主要なカスタマイズ面を、単一の検証済み Tessa 設定から表現
できるようにすることを目標にします。JavaScript やプラグイン VM は埋め込まず、
ライブリロードとプロセスプロトコルで拡張します。0.6 の未完了項目
（レイアウトヘルパー v2、差分プレビュー付き設定エディタ）を先に、または
同時に完了させます。

- [x] inotify による設定自動リロード。デバウンスとトランザクショナルな検証を
      行い、失敗した編集では旧設定を維持する。
- [x] Motion v2 カーブ: 名前付き cubic-bezier、種類別カーブ、開く/
      ワークスペースの開始オフセット、閉じる際のスケール/フェード設定。
- [x] Motion v2 拡張: 正規化スプリングカーブ（`spring = name, damping,
      frequency`）と、ウィンドウ単位のアニメーション有効化・時間・カーブ
      上書き。
- [x] ウィンドウ/レイヤールール v3: ウィンドウ単位の opacity、角丸、ブラー、
      影、ボーダー幅。レイヤーシェル向けルール。タイトル/app-id 変更時の
      装飾系アクションの即時再評価。構造系アクションは map/リロード時のみ。
- [x] 名前付きワークスペース: バーのピル、バインド、IPC コマンド、
      ウィンドウルールの `workspace=` から使えるグローバル名。設定全体を
      読み終えてから解決する。
- [x] スクラッチパッドオーバーレイ: 出力ごとの非表示フローティング
      ウィンドウ。ルールまたはコマンドで割り当て、バインド/IPC で表示切替。
      フォーカスと可視状態も処理する。
- [x] スクラッチパッド以外の special 名前付きワークスペース。
- [x] ウィンドウグループ: ワークスペース上のタイルウィンドウをタブ付き
      グループにまとめ、`Super+Tab` でタブ巡回、グループ追加/削除、IPC 操作。
      グループは実行時状態で永続化しない。
- [x] 入力/出力ポリシー: デバイス別のタッチパッド/マウス設定（タップ、
      自然スクロール、加速、スクロール方式、ボタンマップ）、make/model/
      serial 別モニタールール、VRR/Adaptive Sync、カーソルテーマ/サイズ。
      設定/JSON テストで検証済み。実機のタッチパッドと VRR の挙動は
      ハードウェア検証で確認する。
- [x] 壁紙画像ソース: PNG 背景、cover/contain/stretch、ライブリロード、
      生成グラデーション/アートへのフォールバック。
- [x] シェル v2 の残り: 組み合わせ可能なバーモジュール/レイアウト、
      サーフェス別フォント/配色、壁紙シェーダー、レイヤールール対応の
      ポップオーバーとトースト。
- [x] 常駐プロセスプロトコル経由のシェーダー/エフェクトフック。プロセス内
      プラグイン VM は使わない。
- [x] 性能ガードレール: blur、角丸、アニメーションのヘッドレスベンチマークと
      対象ノート PC でのフレームタイム予算。`tests/performance.sh` が
      アニメーションのみと全エフェクトのワークロードを計測する。実機での
      予算確認はハードウェア検証で行う。

達成条件は、典型的な Hyprland/Niri のテーマとワークフローを 1 つの Tessa
設定から再現でき、ログインし直さずに変更でき、プロセス API で拡張できる
ことです。プラグインの網羅性ではなく、一貫した表現力と検証可能性を重視します。

## 非目標

- TypeScript/JS による設定ランタイムやネイティブプラグイン VM の埋め込み。
  ShojiWM 的なコンポジションに対する Tessa の答えは、宣言的ルールと
  プロセスプロトコルです。拡張コードをコンポジタ内にロードしません。
- Hyprland のすべてのエフェクト/プラグインを追いかけること。Tessa は
  エフェクトの寄せ集めではなく、一貫した静かなデスクトップであり続けます。
- 内蔵ターミナル。kitty/foot の方が急いで作ったターミナルより優れており、
  ターミナルを外部に任せることは最初から許容されています。
